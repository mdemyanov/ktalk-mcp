# ADR-001: документарный контур и гейты nauta в код-проекте

**Дата:** 2026-08-13

## Контекст

`ktalk-mcp` — код-проект: Python-пакет с двумя точками входа. Плагин `nauta` (роли PM/BA/SA/
Dev/QA, гейты, `content/`-контур) был подключён у разработчика на user-scope, то есть работал у
конкретного человека, а не у репозитория: в клоне на другой машине ролей бы не было.

Проектные решения при этом уже принимались — статусная модель реестра, SQLite как source of
truth, чанкинг транскриптов — и записывались либо в `CLAUDE.md`, либо в планы
`docs/superpowers/`, либо нигде. Первое перегружает промт-слой, второе теряется после закрытия
эпика: план отвечает на вопрос «что делать», а не «почему так решили».

Отдельная проблема — гейты. `scripts/` и `.githooks/pre-commit` приезжают из плагина командой
`/nauta:sync-scripts`, но `validate-content.py` возвращает код 2 при отсутствии каталога
`content/`. То есть хук нельзя было активировать, не заведя контур: любой `git commit` падал бы.

## Решение

1. Плагин фиксируется на project-scope в `.claude/settings.json` — вместе с marketplace, чтобы
   свежий клон получал роли без ручной установки.
2. Заводится `content/` по структуре nauta (00-project / 10-domain / 30-requirements /
   40-architecture) с `.doc-root.yaml` — каталог одновременно валиден для Gramax.
3. Активируется `pre-commit` (`core.hooksPath=.githooks`) → `scripts/check.sh --fast`.
4. Пороги гейтов объёма калибруются **по замеру этого репозитория**, а не копируются из шаблона
   (см. [ADR-001-nauta-contour-spec.md](../../40-architecture/ADR-001-nauta-contour-spec.md)).

Границы: `docs/superpowers/` остаётся как есть, ретроспективный перенос планов и спек в контур
не делается. Контур начинает работать с новых фич.

## Последствия

- Каждая статья контура обязана нести свойство «Тип контента» и быть достижимой по ссылке из
  `_index.md` — иначе C12 даёт error, C10 предупреждает о сироте.
- `src/ktalk_mcp/registry.py` (562 строки, класс `Registry` на 208) сработал по C13 в первый же
  прогон и заморожен грандфазером: рост сверх 562 строк блокирует коммит. Это зафиксированный
  долг, а не разрешение — снимается расщеплением класса.
- Гейты запускаются на каждый коммит и требуют `uv` в PATH. Обход разовый — `git commit
  --no-verify`; отключение — `git config --unset core.hooksPath`.

## Альтернативы

- **Оставить user-scope, не заводить контур.** Дёшево, но роли не воспроизводятся в клоне, а
  решения продолжают оседать в `CLAUDE.md`, который гейтится по объёму как раз за это.
- **Завести контур без активации хука.** Валидатор был бы декоративным: нарушения ловились бы
  только при ручном запуске, то есть никогда.
- **Скопировать пороги гейтов из шаблона.** Отвергнуто: `qualityThreshold` шаблона (100–200
  строк) на здешнем корпусе недостижим ни одним файлом — гейт выглядел бы включённым и молчал.
