# ADR-013: Централизованное машинное хранилище транскриптов

**Дата:** 2026-08-18

## Context

Реестр и транскрипты сегодня живут по одному vault'у (`95_TRANSCRIPTS/.registry.db`,
относительно cwd — ADR-002). Требование FR-22/FR-25 и постановка волны 3 переводят их в
машинное хранилище вне проекта-хозяина: записи принадлежат человеку, не проекту, одна встреча
нужна нескольким проектам сразу.

Эталона внутри экосистемы Claude Code plugins нет (RES-001, находка 9): все пять каталогов
`~/.claude/plugins/data/<plugin>-<marketplace>/` на исследуемой машине пусты, официальный
контракт `${CLAUDE_PLUGIN_DATA}` (гарантии при удалении плагина, квоты) не подтверждён
документацией платформы. Пакет `ktalk-mcp` при этом уже сегодня работает как самостоятельный
`uv tool` независимо от установки плагина (RES-001, находка 10) — хранилище не может быть
жёстко привязано к жизненному циклу плагина, если код запускается без него.

На машине наблюдения сосуществуют три паттерна без доминирующей конвенции: Apple-native
(`~/Library/Application Support/`), XDG-буквальный (`~/.local/share/`, использует сосед `uv`) и
top-level dotdir (`~/.claude/`). `$XDG_DATA_HOME` не задан ни на одной проверенной машине.

## Decision

**1. Корень:** `${XDG_DATA_HOME:-$HOME/.local/share}/ktalk` — единый путь на macOS и Linux, без
OS-ветки и без `${CLAUDE_PLUGIN_DATA}`. Алгоритм разрешения и детекция облачной синхронизации —
companion-спека.

**2. Раскладка:**
```
<корень>/
├── registry.db (+ -wal, -shm)   # единственный SQLite-реестр (ADR-002)
├── transcripts/                  # сырые транскрипты, ключ записи в имени файла
└── eval/reports/                 # отчёты качества (аналог 95_TRANSCRIPTS/eval/reports)
```
Протоколы встреч, зеркало `registry.md`, профили участников — артефакты хозяина, в хранилище
не переносятся (NFR-16, детали в спеке).

**3. Приоритет разрешения пути реестра:**
`--db` > `KTALK_REGISTRY_DB` > путь из конфига проекта-хозяина (формат — SA-003) > машинный
дефолт (§1). Расширяет существующую тройку (`config.py`) одним источником между вторым и
третьим местом, не переставляя их (FR-23).

**4. Конкурентный доступ (NFR-13):** новый механизм блокировки не вводится — WAL +
`busy_timeout=5000` + транзакция на операцию (ADR-002) переносится на общий файл без изменений.
Решение здесь — не добавлять слой, а обязать доказать достаточность тестом на двух независимых
процессах (контракт теста — в спеке, задача QA-001).

**5. Облачная синхронизация (NFR-14):** дефолтный корень (§1) не совпадает ни с одним известным
каталогом облачной синхронизации на исследуемой машине. Резолвер дополнительно проверяет
фактически применённый путь (в т.ч. пользовательский оверрайд) эвристикой на признаки
синхронизируемого каталога и предупреждает, не блокируя — алгоритм в спеке.

**6. Права доступа (NFR-15):** каталог создаётся с `0700`, файлы — с `0600`, применяется в
момент первого создания (не ретроактивно к уже существующим файлам).

**7. Миграция (NFR-12):** отдельная явная команда CLI (не `ktalk migrate <vault>` — та уже
занята импортом из markdown-архивов). Семантика копирования, не перемещения: источник
переименовывается в backup-суффикс после построчной сверки дампа, не удаляется; централизованный
файл становится единственным работающим после этого момента. Установка плагина сама по себе
команду не вызывает. Откат — задокументированные шаги в runbook OPS-001, не автоматизация
(соответствует ручному критерию AC NFR-12).

## Consequences

**Positive:**
- Один файл реестра на нескольких хозяев без дублирования состояния (FR-22 AC2).
- Хранилище не зависит от того, установлен ли плагин, — совместимо с сегодняшним `uv tool`.
- Существующий механизм конкурентности (ADR-002) переиспользуется без переписывания.

**Negative:**
- Путь не соответствует Apple-конвенции `Application Support` — сторонние macOS-инструменты
  (Spotlight-метаданные, некоторые бэкап-утилиты, настроенные на этот каталог) хранилище не
  увидят как «приложение».
- Нет ветки под Windows — вне рамок волны (постановка не требует), но `$HOME`-модель развалится
  при появлении такой цели.
- Эвристика детекции облачной синхронизации (§5) не исчерпывающая — платформенного API для
  надёжной проверки нет (RES-001, тема 2), ложноотрицательные случаи возможны.

**Mitigations:**
- Cost Apple-конвенции принят осознанно: пакет — CLI-инструмент, следует паттерну соседнего `uv`
  на той же машине, не GUI-приложению.
- Эвристика документируется как известное ограничение (спека), не выдаётся за гарантию.

## Alternatives Considered

- **`~/Library/Application Support/ktalk/`.** Apple-native, но развилка путей на macOS/Linux
  ради соответствия конвенции GUI-приложений, которой CLI-инструмент не обязан следовать;
  отклонено — цена веток выше пользы соответствия.
- **`${CLAUDE_PLUGIN_DATA}` / `~/.claude/plugins/data/<plugin>-<marketplace>/`.** Адресуем
  плагином (RES-002), но контракт при удалении плагина и квоты не подтверждены документацией
  платформы, а пакет работает и без плагина — привязка source of truth к жизненному циклу
  плагина отклонена.
- **Отдельный dotdir `~/.ktalk/`.** Не хуже технически, но не даёт преимуществ перед
  XDG-буквальным путём и не совпадает ни с одним наблюдаемым на машине паттерном (в отличие от
  `~/.local/share`, где уже живёт `uv`) — отклонено за отсутствием довода в пользу.
