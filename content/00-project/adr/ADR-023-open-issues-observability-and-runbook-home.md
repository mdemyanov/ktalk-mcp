# ADR-023: Обнаружимость подмены транскрипта, момент синхронизации реестра, дом рунбука OPS-001

**Дата:** 2026-09-03

## Context

Три открытых issue пакета `ktalk-cli` требуют архитектурного решения, не покрытого существующими
ADR. [NFR-17](../../30-requirements/transcript-identity-observability.md) (issue #5, вход
[RES-006](../../10-domain/research/2026-09-03-transcript-cross-contamination.md)) требует
клиентскую обнаружимость подмены транскрипта под конкуренцией — причина подмены не локализована,
контракт ответа (`TalkTranscript`, `additionalProperties: false`) не эхо-ит запрошенный ключ.
[FR-41](../../30-requirements/registry-sync-observability.md) (issue #6) требует момент последней
синхронизации реестра в читающей команде без побочной мутации `sync`. Issue #7 фиксирует, что
рунбук отката миграции реестра (ADR-013 §7, capability `centralized-machine-storage`) ссылается на
артефакт OPS-001, которого в дереве физически нет — упомянут в 10 местах, не заведён ни разу
([roadmap.md](../roadmap.md): «Не сделано: … OPS-001»).

## Decision

### 1. Обнаружимость подмены транскрипта (NFR-17)

Новый opt-in флаг `--verify-identity` у `get-transcript`. При передаче CLI выполняет один
дополнительный вызов `get_recording(recording_key)` (не `get_full_participants` — тот для
session-режима удваивает стоимость до 2 вызовов через `get_conference`) и сверяет множество
идентификаторов спикеров транскрипта (`tracks[].speaker`/`diarizedSpeaker`) с множеством
идентификаторов участников записи (`participants`) того же `recording_id`. Результат — одно из
`match` (пересечение непусто), `mismatch` (оба множества непусты и не пересекаются — сигнатура
именно того искажения, что видит RES-006: «другой состав спикеров целиком»), `inconclusive`
(любое множество пусто — сравнивать не с чем), `not_checked` (вызов `get_recording` упал —
основной результат транскрипта при этом всё равно возвращается, AC3). Без флага — поведение и
стоимость команды не меняются, поле `identity_check` в ответе отсутствует.

**Цена:** ровно один HTTP-вызов на транскрипт, только если вызывающая сторона его запросила.
Подмена воспроизводится исключительно под конкуренцией (RES-006) — цена привязана к тому же
условию, не к каждому чтению транскрипта пакетом.

### 2. Момент синхронизации реестра (FR-41)

`ktalk dashboard --json` получает поле верхнего уровня `last_synced` — не в `stats` (тот однородно
`{статус: количество}`, чужеродное поле ломает эту форму) — со значением `Registry.get_meta
("last_synced")` как есть: `null`, если синхронизации не было (AC2 — ключ присутствует, значение
явно `null`, не пропуск и не падение), иначе ISO-8601 дата `YYYY-MM-DD`. Формат записи в
`cli_sync.py:126` не меняется — точность до дня уже достаточна предикату полноты (сверяется с
7-дневным порогом экспирации `sync`, тем же порядком величины); переход на полную метку времени
был бы сменой формата записи без функциональной необходимости, которую issue не заявляет.

### 3. Дом рунбука OPS-001 (issue #7)

Новый раздел `content/70-operations/` (тип контента `Runbook`, уже объявлен в `.doc-root.yaml`,
ни разу не использован) — дом DevOps-рунбуков пакета, параллельный `content/00-project/adr/` по
дисциплине: файл `content/70-operations/OPS-NNN-<slug>.md`, кладбище — `_index.md` раздела.
`.nauta-ids.yaml` получает пространство `ops` (prefix `OPS-`, width 3, definition
`filename-prefix`, allocation `allocated`, home `content/70-operations/OPS-*.md`) — та же форма,
что `adr`, потому что OPS-NNN уже используется как выделенный номерной идентификатор в 10 местах
дерева, просто без дома и без гейта, ловящего коллизию будущего OPS-002. `populated: false`,
`highwater: 0` до первого файла — раздел не материализуется пустым каркасом (правило трёх домов,
прецедент `scenario` в том же реестре): DevOps заводит `OPS-001-…md` и поднимает `populated`/
`highwater` тем же коммитом, что и файл.

Пустой каталог из шаблона плагина домом не был бы (в дереве такого каталога и не было — `ls
content/` подтверждает отсутствие `70-operations/` до этого решения) — дом здесь заводится решением
SA, не наследуется молча.

## Consequences

**Positive:**
- NFR-17: у потребителя (в т.ч. промт-слой плагина 1.10.0, уже делающего эту проверку вручную
  двумя вызовами) появляется единая, тестируемая на уровне пакета точка проверки вместо дублирования
  логики по каждому вызывающему.
- FR-41: предикат полноты разбора больше не может отдать «зелёный ноль» на данных недельной
  давности молча.
- OPS-001: у рунбука отката (ADR-013 §7) появляется адресуемый дом; будущие рунбуки (например,
  cutover OPS-001 из ADR-012-spec — другой предмет, тот же номер по историческому совпадению текста
  issue, не по факту) получают то же место без повторного архитектурного решения.

**Negative:**
- NFR-17: `mismatch` при системе с нестабильными `anonymousId` для гостей (генерируемыми заново
  на сессию) может ложно сработать на легитимном транскрипте с анонимными участниками — не
  проверено живым тестом (нет санкции, см. RES-006).
- FR-41: точность до дня не даёт отличить синхронизацию час назад от синхронизации утром того же
  дня — достаточно заявленному предикату (сравнение с 7-дневным порогом), недостаточно гипотетическому
  более строгому потребителю, которого требование не называет.
- OPS-001: новое пространство идентификаторов — на одну запись реестра больше для сверки
  `id-check.sh --full`.

**Mitigations:**
- NFR-17: ограничение анонимных участников документируется как известное в companion-спеке, не
  скрывается; `inconclusive` — честный третий исход именно для случаев, где сравнивать не с чем.
- FR-41: если потребителю понадобится более точный момент — расширение формата является
  отдельным решением с отдельным issue, не форсируется здесь без заявленной необходимости.

## Alternatives Considered

- **NFR-17, эхо-поле в ответе транскрипта.** Контракт `TalkTranscript` не несёт поля,
  возвращающего эхом `recordingKey`/`conferenceKey` (RES-006) — опции физически нет.
- **NFR-17, вывод `transcriptId` в `--json`.** `transcriptId` — идентификатор транскрипта, не
  записи, и получен из ТОГО ЖЕ потенциально скомпрометированного ответа — не независимый источник,
  которого требует NFR-17 дословно; отклонено.
- **NFR-17, обязательная проверка на каждом вызове `get-transcript`.** Удваивает стоимость каждого
  чтения ради риска, воспроизводимого только под конкуренцией — цена непропорциональна условию;
  отклонено в пользу opt-in.
- **NFR-17, `get_full_participants` вместо `get_recording`.** Точнее (полный смёрженный список), но
  для session-режима — 2 сетевых вызова вместо 1; для обнаружения полного несовпадения состава
  (симптом RES-006) точность `get_recording.participants` достаточна — отклонено по цене.
- **FR-41, поле в блоке `stats`.** Предложение issue #6; отклонено — `stats` однородный
  `{статус: int}`, добавление строки ломает эту форму для любого потребителя, итерирующего по нему.
- **OPS-001, `content/60-implementation/` как дом.** Тот дом — заметки Dev о расхождении реализации
  со спекой, не операционные процедуры DevOps; предмет другой, отклонено.
