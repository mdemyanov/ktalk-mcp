# AT-design: пара «требование → openspec/specs/<capability>/spec.md» (QA-001/QA-002)

Тест-дизайн эпика `ktalk-plugin-56l` со стороны дерева пакета. Источники:
[ADR-021](../00-project/adr/ADR-021-requirement-capability-pairing.md),
[companion-спека](ADR-021-requirement-capability-pairing-spec.md) §1-4.

Предмет эпика — документы и гейты, не код: стаб здесь — прогон `scripts/check.sh` и grep
по дереву. Дерево сейчас зелёное (`Errors: 0`, `check.sh --full` exit 0), восемь
capability-спек написаны, три требования несут `**Capability:**` — стаб проверяет исход, а
не отсутствие файла.

Стаб: [scripts/test-requirement-capability-pairing.sh](../../scripts/test-requirement-capability-pairing.sh)
(`bash scripts/test-requirement-capability-pairing.sh`).

## Ревизия QA-002: два ожидания не пережили исполнение

Первый раунд (QA-001) кодировал два решения буквально; оба были исправлены по факту
исполнения, стаб приведён следом — не ослаблен до тавтологии «что вижу, то и ожидаю»:

1. **PAIR-2.** Решение о переезде поменялось: перемещается СОДЕРЖАНИЕ, не путь. Удаление
   четырёх оригиналов давало 34 битые ссылки в 22 документах дерева пакета (пять ADR,
   `roadmap.md`, спек-компаньоны, security-review, заметки Dev) — все исторические, решения
   принимались *против* этих требований, и стирание файла превратило бы факт «решено против
   X» в ложь об истории. На старых путях остаются файлы-указатели: `Тип контента: Прочее`,
   `Статус: Approved`, без каркаса FR/NFR, с адресом нового файла (ADR-023 Д1, дерево
   плагина, ревизия после исполнения). PAIR-2 больше не проверяет «файла нет» — это ожидание
   стало неверным; проверяет три независимых признака, отличающих указатель от требования,
   которое могло бы «воскреснуть» на старом пути.
2. **PAIR-5.** ADR-021 п.4 предписывал `populated: true` тем же коммитом, что первая спека.
   Предписание было неисполнимо: `id-check.sh:527-533` — пустой `prefix` при
   `allocation: derived` делает сочетание с `populated: true` ПОРЧЕЙ реестра (`ERROR`, не
   «не смог проверить»), потому что у записи с пустым prefix номеров нет по построению.
   ADR-021 и companion-спека исправлены — `populated: false` у `scenario` теперь постоянный
   инвариант, не флаг «до первой спеки». PAIR-5 проверяет именно это: `false` независимо от
   числа спек (сейчас — 8), не переключение по их наличию.

Оба расхождения нашёл именно этот стаб на живом дереве (`PASS=24 FAIL=5` до ревизии) — он и
остаётся единственным прибором, который их видит; следующий такой же дрейф стаб обязан ловить
так же явно, не тише.

## Boundary cases

- Файл требования несёт **несколько** строк `**Capability:**` через запятую в одной строке
  или несколько строк подряд — обе формы валидны (`_declared_capability_paths` разбирает
  список, companion-спека §3). `check_capability_line` в стабе не привязан к одной из двух
  форм — сравнивает МНОЖЕСТВО извлечённых slug'ов, не сырой текст строки.
- Capability одного файла требования пишется одним заходом, не вперемешку с другими файлами
  (companion-спека §3, «Порядок») — граница проверки PAIR-3 идёт по файлу требования, не по
  отдельной capability, чтобы не засчитать частичный прогресс как «готово».

## Error cases (два обязательных класса)

**Malformed/mistyped input** (не отсутствие значения, а искажённое значение от того, кто
пишет строку `**Capability:**`/правит файл-указатель — целевой «пользователь» этого
механизма — Dev/задача-автор спек, не конечный оператор Толка):
- PAIR-3, ветка "исход C": Dev называет несуществующий или неверно набранный slug
  (например, `openspec/specs/talk-api-auth/spec.md` вместо `talk-api-auth-modes`) — путь
  ФОРМЫ `openspec/specs/<slug>/spec.md`, но набор slug'ов не совпадает с ожидаемым по
  ADR-021-spec §1 — стаб ловит несовпадением множеств, не только `is_file()`.
- PAIR-3, ветка "исход D": slug той же формы, но директория/файл ещё не создана (опечатка в
  имени capability при копипасте) — стаб ловит явным `-f` для каждого объявленного пути.
- PAIR-2: адрес нового файла в теле указателя набран с опечаткой/устарел после
  переименования — `check_pointer` ищет буквальную подстроку нового имени файла, опечатка
  или устаревший адрес не проходят молча.

**Masked failure** (система молчаливо принимает решение вместо явной ошибки):
- PAIR-7: если `auth-status` тихо получит собственную директорию `openspec/specs/auth-status/`
  вместо того чтобы остаться сценарием внутри `talk-api-auth-modes` — ни один существующий
  гейт (C15/C16) этого не поймает: обе формы синтаксически валидны, различие чисто
  архитектурное (решение SA, не BA). Без PAIR-7 дрейф границы capability прошёл бы тихо.
- PAIR-5 (ревизован QA-002): если кто-то поднимет `scenario.populated` на `true`, «увидев
  восемь спек» и приняв старое (уже отменённое) предписание ADR-021 п.4 за живое —
  `id-check.sh` тут же даёт `ERROR: реестр повреждён` (проверено мутацией, см. отчёт), но
  БЕЗ PAIR-5 в стабе этот класс регресса был бы виден только в `--full` — `--fast` его не
  запускает вовсе (`id-check.sh` живёт только в `--full`), то есть до следующего `--full`
  расхождение осталось бы невидимым.
- PAIR-2 (ревизован QA-002): файл-указатель мог бы тихо перестать быть указателем —
  накопить обратно каркас FR/NFR или сменить `Тип контента` на `Требование` — без единого
  сигнала: `check_capability_link` (C15) молчит про файлы типа `Прочее` по построению
  (`_type_content_value(fm) != "Требование": continue`), то есть возврат содержания на
  старый путь прошёл бы МИМО главного гейта дерева. PAIR-2 — единственная проверка, которая
  это видит.

## Не покрывается (out of scope этого стаба)

- Сам механизм `check_capability_link` (все 4 исхода в общем виде, на синтетических
  фикстурах) — тестирует сьют донора `scripts/test-validate-content.sh`, не этот стаб
  («Контракт с QA-author» companion-спеки ADR-021-spec: «не тестируется... сам механизм пары
  `**Capability:**`»). Здесь проверяется исход на КОНКРЕТНЫХ 8 строках этого эпика, не общее
  свойство валидатора.
- Текст самих 8 спек (нормативные `#### Scenario:`, полнота покрытия FR/NFR трёх требований)
  — предмет задачи-автора спек и её собственного QA-цикла, не этого AT-дизайна уровня эпика.
