# ADR-001 spec: калибровка гейтов объёма

Companion-спека к [ADR-001](../00-project/adr/ADR-001-nauta-contour.md). Здесь — замер, на
котором стоят пороги в [.nauta-gates.yaml](../../.nauta-gates.yaml), и правило их пересмотра.

## Как устроен гейт C13

Парная метрика: сигнал только если сработали **оба** признака.

1. Количественный — число строк файла больше `thresholdLines` (T).
2. Качественный — самая длинная top-level декларация не короче `qualityThreshold` (T_S).

Файл на 400 строк из тридцати коротких функций проходит молча: это контейнер, а не стена.
Файл на 400 строк из одного класса на 250 — срабатывает. Перечисление файлов идёт через
`git ls-files`, поэтому `.gitignore` наследуется даром; `.sh` и `.md` под C13 не попадают.

## Замер 2026-08-13

Все `.py` под git, отсортировано по числу строк. `decl` — длиннейшая top-level декларация,
посчитана тем же `PY_DECL_RE`, которым меряет валидатор.

## Выбранные пороги и почему

**prod: T=350, T_S=100, severity block.** Единственное срабатывание сегодня —
`registry.py`: 562 строки при классе `Registry` на 208. Это и есть та самая стена, ради которой
гейт заводится. `formatters.py` при 370 строках проходит молча (decl=51 — тридцать коротких
форматтеров), и это правильный исход, а не дырка в гейте. `client.py` с decl=87 на 104 строках
не добирает по количественному признаку — короткий файл из одного класса нормален.

**test: T=600, T_S=150, severity warn.** Тестовый файл длинный по природе, а его «декларация» —
это класс-группировка тестов, не единица сложности. T_S=150 при максимуме 109 означает: сегодня
не срабатывает никто, включая `test_formatters.py` на 652 строках. Порог живой — сработает
тест-класс, разросшийся в полтора раза сверх нынешнего максимума. `warn`, а не `block`:
разрастание тестов — сигнал к рефакторингу, но не повод блокировать коммит.

**Промт-слой (C14): T=200, severity block.** Сумма строк `CLAUDE.md` + `AGENTS.md`. `AGENTS.md`
в проекте нет — отсутствующий файл даёт 0 к сумме, это штатный исход, не ошибка. Порог оставляет
запас к нынешнему размеру `CLAUDE.md` и упирается ровно в то, ради чего гейт существует: промт-
слой тратит контекстное окно на каждом запуске, независимо от того, насколько он структурирован.

**content/ (C11): только тип ADR, T=150, quality companion-spec, block.** Шаблонное значение
принято без правки — ADR фиксирует решение, а не процедуру; детализация уезжает в такую вот
companion-спеку. Остальные типы записи не имеют осознанно: калибровать не по чему, корпус
пустой. Появится десяток статей типа — заводить запись тем же коммитом, что и десятую статью.

## Грандфазер

Три записи, и они разной природы.

**`src/ktalk_mcp/registry.py`, ceiling 562** — наш долг. Фактический размер на день включения:
пока файл на 562 строках, C13 печатает warning и пропускает; 563-я строка даёт error и
блокирует коммит. Снимается расщеплением `Registry` (парсеры и мапперы API → отдельный модуль,
класс оставить на CRUD), после чего строка удаляется. Поднимать ceiling вместо расщепления —
легальный, но осознанный шаг: он делается явной правкой того же файла в том же коммите, чтобы
решение было видно в diff, а не растворилось в росте.

**`scripts/_drift_check.py` (487) и `scripts/validate-profile.py` (652)** — не наш долг, а
payload плагина. C13 перечисляет файлы через `git ls-files` и не поддерживает исключение путей:
вендоренные скрипты гейтятся наравне с собственным кодом. Расщепить их нельзя — следующий
`/nauta:sync-scripts` перезапишет правку, а конфликт-детекция по sha256 вычеркнет файл из
обновлений совсем.

Потолки этих двух зафиксированы по версии плагина 0.5.0. Обновление payload'а может
заблокировать коммит — тогда потолок обновляется под новый размер. Это операция обслуживания,
а не решение о долге, и путать их не надо: у первой записи рост означает «пора расщеплять», у
двух остальных — «плагин обновился».

Ближайший кандидат на третье срабатывание — `scripts/_resolve_agents.py`: 311 строк при T=350
и decl=134 при T_S=100, то есть качественный признак уже провален, не хватает 39 строк по
количественному.

## Известный зазор

Если бы `.py` payload'а можно было исключить по пути, обе вендоренные записи были бы не нужны.
Механизма нет — C13 знает только пару `extension`+`kind`, а `kind` вычисляется по сегментам
пути `tests`/`test`. Обходные пути, которые рассматривались и отвергнуты:

- **Поднять T выше 652**, чтобы payload проходил — убило бы гейт для собственного кода:
  `registry.py` (562) перестал бы ловиться, ради чего гейт и заводился.
- **Не держать `scripts/` под git** — тогда в свежем клоне payload'а нет, `pre-commit` печатает
  «scripts/check.sh не найден; pre-commit skipped» и молча пропускает коммит. Это ровно тот
  исход «не проверялось выглядит как нарушений нет», против которого весь этот контур.

## Когда пересматривать пороги

- Появился новый язык в репозитории → завести пару записей `extension`+`kind`, иначе файлы
  этого расширения не гейтятся вовсе (это статус «не измерено», а не «нарушений нет»).
- Гейт молчит полгода при явном росте файлов → T_S завышен, перемерить.
- Гейт срабатывает на каждом втором коммите → T занижен либо в проекте реальный долг.
