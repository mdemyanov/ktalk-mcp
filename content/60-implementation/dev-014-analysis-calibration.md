# DEV-014: калибровка промт-слоя анализа плагина ktalk

Реализация [ADR-018](../00-project/adr/ADR-018-analysis-calibration.md) и
[ADR-018 spec](../40-architecture/ADR-018-analysis-calibration-spec.md) по
[требованию FR-40…FR-43, NFR-25](../30-requirements/ktalk-plugin-analysis-calibration.md).
Правки — целиком в репозитории плагина `ktalk`, ветка `dev-014-analysis-calibration`,
два коммита: `755b03f` (первый проход) и `81e09c4` (правки по код-ревью координатора —
см. «Правки по код-ревью» ниже), поверх `origin/main` `0bfd53a` (плагин синхронизирован
ff-only оркестратором, не мной — операция `git merge` роли `nauta:dev-agent`
недоступна по ADR-036 Д5/Д6, уровень запрета 1; см. лог диалога). Пакет `ktalk-mcp`
не тронут — вне периметра решения (ADR-012 §1).

## Расхождения со спекой (не молчаливые)

**1. Место объявления маркера `[ASR?]` — вне кода-шаблона, не внутри секции «Открытые
вопросы».** Спека (§1.2) требует абзац «рядом с существующим объявлением `[UNCLEAR]`»,
не фиксируя буквально — внутри тройного markdown-блока шаблона или снаружи, в прозе
документа. Первая попытка вставила абзац внутрь блока ```` ```markdown ... ``` ````,
между строкой `- [UNCLEAR] {описание}` и заголовком `## Флаги для владельца проекта`.
Решил, что это ошибка: весь блок — буквальный шаблон, который `ktalk-processor`
воспроизводит структурно (секции, плейсхолдеры); объяснение синтаксиса маркера —
не часть выходного протокола, а инструкция для агента о том, как писать имена. Перенёс
абзац за закрывающий бэктик блока, рядом со строкой «Порядок секций» (тоже прозой, не
частью шаблона). Секция «Ключевые тезисы» осталась внутри блока — она, в отличие от
объявления синтаксиса, действительно часть выводимого протокола.

**2. `_meta.md`: обнаружен и не устранён задним числом дрейф `prompt_version` vs
changelog.** До этой правки frontmatter держал `prompt_version: 1`, при этом секция
«Prompt versions» того же файла уже фиксировала v2 (2026-04-03, few-shot примеры,
extraction checklist) как текущую — расхождение существовало до DEV-014, не создано
им. Спека предписывает буквально «`prompt_version` увеличивается на 1» — выполнил
буквально (1→2), не пересчитал историю. Отметил находку текстом в «Prompt versions»
файла (не только здесь) — иначе следующий, кто откроет `_meta.md`, увидит второй `v2`
без объяснения и решит, что это опечатка правки DEV-014, а не унаследованный факт.

**3. Гейт NFR-25 сравнивает базу с рабочим деревом (two-dot `git diff <ref> -- path`),
не с закоммиченным `HEAD` (three-dot `<ref>...HEAD`).** Первая редакция скрипта
использовала `origin/main...HEAD` — на branch без коммитов поверх базы диапазон пуст,
и гейт тривиально проходил, не видя реальных незакоммиченных изменений: ложный
«зелёный» на состоянии, которое и обязано было упасть. Перепроверил на пустом diff
(до коммита) — обнаружил трюк экспериментально, не по спеке (спека не уточняет форму
diff). Two-dot форма видит и рабочее дерево (актуально для pre-commit до коммита), и
совпадает с three-dot после коммита (когда working tree == HEAD) — единая формула для
обоих контекстов вызова.

## Правки по код-ревью координатора (коммит `81e09c4`)

Первый проход (`755b03f`) прошёл гейт и `check.sh --fast`, но не закрывал требование
полностью — три находки координатора, каждая подтверждена командой до правки:

**1. FR-42 AC3 (деградация без каталога) не имело нормативного текста.**
`grep -rn "не объявлен\|деград" skills/ktalk-registry/references/analysis-quality.md
agents/references/protocol-template.md agents/ktalk-processor.md` до правки находил
только текст про недоступность шага целиком (FR-24), не про обязанность маркировать
все сомнительные имена при недоступности резолвинга. Правка: `analysis-quality.md`
§1 получил абзац «деградация не означает молчаливый пропуск маркировки»; §1а получил
нормативный блок «имя, не резолвившееся (каталог не нашёл совпадения ИЛИ каталог/`qmd`
недоступны вовсе — оба случая равнозначны) — помечается `[ASR?]` всегда».

**2. §10 `analysis-quality.md` — исторический источник дефекта — остался нетронутым.**
Требование прямо называет §10 корнем проблемы: маркировка предписана только для
участников. Первый проход добавил §1/§1а параллельно, не тронув §10 — тот продолжал
бы перебивать новые правила тем же механизмом, каким Пример 3 перебивал §4 до этой
задачи (конкретный текст рядом с местом работы модели весит больше абстрактного
правила в другом разделе). Правка: §10 переписан — третьи лица наравне с участниками,
`[ASR?]` вместо «не записывать искажённую фамилию» (молчаливое действие без
маркировки), явная нормативная связка с §1/§1а.

**3. Гейт NFR-25 проверял факт изменения `plugin.json` (`git diff --name-only`), не
значение `version`.** Правка одного `description` без изменения `version` давала
ложный `OK` — гейт видел файл в diff и считал условие выполненным. AC NFR-25 требует
буквально «minor-версия плагина поднята». Переписал `check_prompt_version_sync`:
читает строку `version` из `base_ref` (`git show`) и рабочего дерева (`grep`),
сравнивает `(major, minor)` как кортеж, требует строгого роста. **Выбор:** именно
minor (или выше — major тоже проходит, он строго больше), patch-only (`1.2.1→1.2.2`)
не проходит — patch в этом проекте зарезервирован под правки вне промт-слоя
(например, README), calibration — не patch-уровня правка по семантике версии,
использованной в этой же задаче (`1.2.1→1.3.0`, не `1.2.2`). Если координатор не
согласен с этим выбором (принимать и patch) — открытый вопрос, решение примет он.

## Статические проверки FR-42 AC2 (сверх обязательного минимума)

- `grep -rn '\[ASR' agents/ skills/ktalk-registry/` — единственная точка объявления
  синтаксиса `[ASR?]` — `agents/references/protocol-template.md`; остальные вхождения
  (`_meta.md`, `analysis-quality.md`) используют форму без вариаций.
- `grep -rn '\[UNCLEAR:' agents/ skills/ktalk-registry/` — оба найденных вхождения
  (`analysis-quality.md`, примеры «Пример 1») относятся к синтаксису открытых вопросов,
  существовавшему до этой правки, не к варианту маркера имени; коллизии форм
  `[UNCLEAR: ..., ASR]`/`[ASR, ...]`, которую отклоняла ADR-018 «Альтернативы», в
  дереве плагина после правки нет.

## Что осталось непроверенным

- **A/B-прогон `ktalk-eval` на трёх записях замера** (спецификация §3 таблица) — не
  выполнен в этой задаче; проверка регрессионных пар FR-41 AC1/AC2, реального
  срабатывания шага 4.5 на status-встрече и резолвинга третьих лиц на 1-1-записи
  требует реального вызова LLM-агента на фикстурах записей, вне периметра статической
  правки промт-текста. Ссылка на трекер оценки — задача следующего цикла (владелец
  прогона не определён этим решением).
- **Подключение `check-plugin-composition.sh` к CI/pre-commit репозитория `ktalk-plugin`**
  — не проверено; предпосылка ADR-018 явно возлагает подтверждение на DevOps того
  репозитория, вне периметра ADR-012.
- **Омонимия при резолвинге третьих лиц** (частичное совпадение с несколькими
  профилями каталога) — открытый вопрос требования, не решён этой правкой (решение
  явно оставлено на будущую калибровку при находке на записях).
- **`ktalk-mcp`: `bash scripts/check.sh --fast`** — прогнан после правок в `ktalk-plugin`,
  не должен был измениться (промт-слой лежит вне этого пакета); фактический результат
  ниже.
