# DEV-006: промт-слой плагина ktalk для встреч (волна 5)

Реализация SA-006 (`content/40-architecture/ktalk-plugin-meetings-spec.md`) в репозитории
`ktalk-plugin` (отдельный git-репозиторий) + версионный узел в этом пакете.

## Добавлено (репозиторий `ktalk-plugin`)

- `skills/ktalk-meetings/SKILL.md` — новый навык, шесть секций в порядке FR-32→FR-38: предусловие
  онбординга (дословно скопирован блок из `ktalk-registry`/`ktalk-eval`) → «Диагностика при
  отказе» (общая, FR-37/FR-38) → «Расписание» (FR-32) → «Создание встречи» (FR-33, с handoff
  дословно из SA-006) → «Отмена встречи» (FR-34, handoff дословно) → «Поиск участника» (FR-35) →
  «Диагностика комнаты» (FR-36, предупреждение дословно из SA-006/ADR-006).
- `skills/ktalk-meetings/_meta.md` — по конвенции соседних навыков (`ktalk-eval/_meta.md`).
- `scripts/check-plugin-composition.sh` — шестой `check` (grep MCP-имён операций встреч, NFR-20),
  4 существующих не тронуты.
- `.claude-plugin/plugin.json` — версия `1.0.0` → `1.1.0`.
- `compat.json` — `ktalk_mcp_min_version` `0.7.0` → `0.8.0` (см. «Версионный узел»).

## Добавлено (этот репозиторий, `ktalk-mcp`)

- `pyproject.toml` — версия `0.7.0` → `0.8.0`. Публикация в PyPI не выполнена — операция
  владельца (см. «Незакрытое»).

## Версионный узел

Контракт CLI, на который опирается новый навык (`--json` на `create-meeting-preview`/
`cancel-meeting-preview`/`search-contacts`, три кода возврата `search-contacts`), появился в
DEV-009 и не был выпущен под новым номером пакета — `pyproject.toml` оставался `0.7.0`, той же
версией, что уже опубликована в PyPI. Навык `ktalk-meetings`, написанный под этот контракт, не
может работать корректно против опубликованной `0.7.0` (нет `--json` на трёх командах, у
`search-contacts` только два кода возврата вместо трёх — секция «Поиск участника» ждёт код `2`,
которого `0.7.0` не отдаёт).

Закрыто здесь: `pyproject.toml` поднят до `0.8.0`, `compat.json` плагина — `0.8.0`. До публикации
`0.8.0` в PyPI `ktalk-onboard.sh check` у пользователей на опубликованной `0.7.0` будет честно
сообщать о несовместимости (код 11, `references/onboarding.md`, «Код 11 — версия ниже
минимальной») — это ожидаемое, спроектированное состояние заморозки, а не дефект: механизм
`compat.json`/`check` для этого и существует (DEV-005, ADR-014). Работу можно продолжать (тот же
файл: «несовместимость версии — предупреждение, не блокировка»), часть сценариев (навык
`ktalk-meetings`) не будет работать до публикации.

## Где реализация разошлась со спекой SA-006 и почему

- SA-006 (строка «Развилки», `compat.json`) отметила, что решение о номере релиза и правке
  `compat.json` — задача выпуска, не эта. Формулировка задачи DEV-006 (постановка волны 5, брифинг
  этого запуска) явно отдала версионный узел этой задаче — приоритет более свежей и конкретной
  постановки над более общей формулировкой SA-006, без противоречия по существу (SA-006 не
  запрещала, а откладывала).
- Секция «Связанные команды» в `SKILL.md` — не часть состава, зафиксированного SA-006 (компоненты:
  только сам `SKILL.md` + `check-plugin-composition.sh` + `plugin.json`), добавлена по прецеденту
  `ktalk-eval`/`ktalk-registry` (обе несут такую таблицу) для единообразия дерева — не меняет
  контракт FR/NFR, чисто справочная секция.
- Раздел «Раскладка каталогов проекта-хозяина этому навыку не нужна» — явное утверждение, которого
  нет буквально в SA-006, но прямо следует из «Развилок» («Новые ключи `.ktalk.toml` — не нужны»);
  добавлено для симметрии с предусловием `ktalk-registry`/`ktalk-eval` (обе секции явно называют,
  что раскладка читается) — здесь явно называет, что не читается, чтобы не оставлять вопрос
  открытым для следующего Dev.

Текст handoff-сообщений (FR-33/FR-34) и предупреждения `get-room` (FR-36) — скопированы дословно
из SA-006, без правок.

## Что осталось незакрытым

- Публикация пакета `ktalk-mcp` 0.8.0 в PyPI — операция владельца (по прецеденту DEV-005/PyPI-note
  в auto-memory), не выполняется этой задачей.
- 15 красных стабов QA-005 в `tests/` этого репозитория — контракт на поведение CLI
  (`list-calendar`/`get-room`/`cancel-meeting-*`/`AC-37-1`/`AC-38-1`), не на состав плагина; не
  трогались, остаются красными (DEV-009 их тоже не закрывала).
- Живая проверка навыка `ktalk-meetings` против боевого контура — не выполнялась (боевых запросов
  к KTalk не делать — ограничение задачи); проверка после публикации 0.8.0 — отдельная задача.
- Команда `/ktalk-meetings` (SA-006, «Развилки»: открыто для Dev на будущее, если операторы не
  находят навык через авто-роутинг) — не заведена, решение SA-006 явно откладывает это.
