# Transcript Chunking Design

## Context

Транскрипты длинных записей KTalk могут содержать десятки тысяч символов, что превышает
комфортный размер контекста для LLM-агентов. Нужен механизм автоматического разбиения
результата `ktalk_get_transcript` на чанки с метаданными для постраничного чтения.

## Решение: Format-then-split

Подход: сначала форматируем полный транскрипт (markdown/raw), затем нарезаем готовый текст
на чанки по границам реплик. Formatter (`format_transcript`) не меняется.

## Сигнатура tool

```python
@mcp.tool()
async def ktalk_get_transcript(
    recording_key: str,
    format: str = "markdown",
    chunk: int = 0,           # 0 = авто, 1+ = конкретный чанк
    chunk_size: int = 30000,  # мягкий лимит символов (~7500 токенов)
) -> str:
```

## Поведение chunk параметра

### chunk=0 (авто, по умолчанию)
- Форматируем полный транскрипт
- Если `len(result) <= chunk_size` → возвращаем как есть (строка, обратная совместимость)
- Если `len(result) > chunk_size` → нарезаем, возвращаем **первый чанк** с метаданными

### chunk=N (N >= 1)
- Форматируем полный транскрипт → нарезаем → возвращаем чанк N с метаданными
- Если N > total_chunks → ошибка: `"Чанк N не существует. Всего чанков: M"`

## Формат ответа с метаданными

Когда ответ нарезан (авто или явный запрос), возвращается JSON-строка:

```json
{
  "result": "# Транскрипт\n\n**Демьянов Максим** [00:00:00]: ...",
  "chunk": 1,
  "total_chunks": 3,
  "has_more": true,
  "total_characters": 73000
}
```

## Алгоритм нарезки: markdown

Функция `chunk_transcript_markdown(text: str, chunk_size: int) -> list[str]` в `formatters.py`:

1. Отделить заголовок `# Транскрипт\n\n` от тела
2. Разбить тело по `\n\n` — каждый элемент = одна реплика
3. Жадно накапливать реплики в текущий чанк:
   - Пока `len(header) + len(accumulated) + len(next_utterance) <= chunk_size` → добавляем
   - Иначе → завершаем текущий чанк, начинаем новый
4. К каждому чанку добавить заголовок `# Транскрипт\n\n`
5. Одна реплика > chunk_size — оставляем целиком (не разрываем)

## Алгоритм нарезки: raw

Функция `chunk_transcript_raw(data: dict, chunk_size: int) -> list[str]` в `formatters.py`:

При чанкинге raw формата (chunk >= 1 или авто-чанк):
1. Извлечь и отсортировать реплики из `data["tracks"]` (как в `format_transcript`)
2. Каждая реплика → JSON-объект: `{"speaker": "Фамилия Имя", "timestamp_ms": N, "text": "..."}`
3. Группировать объекты в чанки по `chunk_size` (сериализованная длина)
4. Каждый чанк сериализуется как JSON-массив с `indent=2`

При chunk=0 и размер <= chunk_size — raw возвращает полный API-ответ как сейчас (`json.dumps(data)`).

## Структура изменений

### formatters.py
- **Добавить:** `chunk_transcript_markdown(text: str, chunk_size: int) -> list[str]`
- **Добавить:** `chunk_transcript_raw(data: dict, chunk_size: int) -> list[str]`
- `format_transcript` — **без изменений**

### server.py
- **Изменить:** `ktalk_get_transcript` — добавить параметры `chunk`, `chunk_size`
- **Добавить:** логику оркестрации: формат → проверка размера → чанкинг → метаданные

### tests/test_formatters.py
- **Добавить:** тесты `chunk_transcript_markdown`:
  - Текст меньше chunk_size → один чанк
  - Текст больше chunk_size → несколько чанков по границам реплик
  - Одна длинная реплика → не разрывается
  - Пустой транскрипт → один чанк
- **Добавить:** тесты `chunk_transcript_raw`:
  - Аналогичные кейсы для raw формата

### tests/test_server.py (или интеграционные тесты)
- Тест chunk=0 с коротким транскриптом → строка (обратная совместимость)
- Тест chunk=0 с длинным транскриптом → JSON с метаданными, chunk=1
- Тест chunk=2 → второй чанк с метаданными
- Тест chunk > total → ошибка

## Уточнения

- `chunk_size` применяется к тексту результата (поле `result`), не к JSON-обёртке с метаданными
- `total_characters` — длина полного отформатированного транскрипта (markdown или raw)

## Правила нарезки

- Резать **между репликами**, не внутри
- `chunk_size` — **мягкий лимит**: чанк может быть меньше, чтобы не разрывать реплику
- Если одна реплика > chunk_size — она становится отдельным чанком целиком
- Заголовок `# Транскрипт` включается в каждый чанк (для markdown)
- Рекомендуемый chunk_size: 30,000 символов (~7,500 токенов)
